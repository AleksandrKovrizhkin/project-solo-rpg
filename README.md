# project-solo-rpg

## MVP: SoloRPG в Telegram (одиночная игра, строгие правила, RU)

### 1) Критика и корректировка идеи
- **LLM не должен решать механику.** Он «рассказчик и мастер сцены», а правила и броски — в коде.
- **Состояние игры обязательно.** Без хранилища сессий всё развалится при ретраях/дублях сообщений.
- **Слой управления правилами нужен сразу.** Иначе модель будет «галлюцинировать» правила.

### 2) Архитектура (минимально‑надёжная)
**Telegram webhook → Cloudflare Worker → OpenRouter → D1 (данные) + KV (идемпотентность)**

- **Worker**: принимает апдейты от Telegram, запускает движок правил, вызывает LLM.
- **D1**: хранит игроков, сессии, состояния, журнал ходов.
- **KV**: хранит обработанные update_id (защита от дублей Telegram).

### 3) Структура данных (D1)
**players**
- id (pk)
- telegram_user_id
- display_name
- created_at

**sessions**
- id (pk)
- player_id (fk -> players.id)
- status (active/paused/ended)
- ruleset_version
- created_at
- updated_at

**party_members** (NPC + игрок)
- id (pk)
- session_id (fk -> sessions.id)
- name
- role (player/npc)
- stats_json
- hp
- inventory_json

**turns** (журнал)
- id (pk)
- session_id (fk -> sessions.id)
- turn_index
- player_input
- gm_output
- rules_trace_json (что и как считалось)
- created_at

**memory_summary** (сжатая память)
- session_id (pk)
- summary_text
- updated_at

### 4) Поток обработки сообщения
1. Получить update_id и message.text.
2. Проверить KV: если update_id уже обработан — выйти.
3. Загрузить активную сессию игрока.
4. Считать `memory_summary + последние 3–5 turns`.
5. **Запустить движок правил**: броски, проверки, урон и т.п.
6. **Собрать prompt** и вызвать OpenRouter.
7. Сохранить новый turn + обновить summary.
8. Ответить в Telegram.

### 5) Минимальный ruleset (строгая механика)
- **Проверка навыка**: d20 + модификатор против DC.
- **Бой**: очередь по инициативе, базовый урон, HP.
- **Инвентарь**: предметы с простыми тегами (heal, dmg, key).
- **NPC**: те же правила, но ходят по авто-логике.

### 6) Минимальный prompt (RU)
**System** (вшить жестко):
```
Ты — гейм-мастер. Следуй правилам из блока RULES.
НЕ меняй механику. НЕ придумывай новые правила.
Говори по-русски. Кратко, ясно, без воды.
```

**RULES** (вшить из кода):
```
- Проверки: d20 + модификатор против DC.
- Бой: инициатива, ход по очереди.
- Если механика решена кодом, опиши результат без пересчёта.
```

**MEMORY** (summary_text)

**LAST_TURNS** (3–5 последних ходов)

**USER_INPUT**

### 7) MVP‑план (шаги)
1. **Создать Telegram бота** и получить токен.
2. **Завести Cloudflare Worker** (webhook, один endpoint).
3. **Подключить D1 + KV** и создать таблицы.
4. **Сделать rules‑engine** (d20, DC, HP, инвентарь).
5. **Подключить OpenRouter** и собрать prompt.
6. **Сделать базовую игру**: стартовая сцена, 1–2 квеста.
7. **Логи и отладка**: сохранять rules_trace_json и ошибки.

### 8) Что можно улучшить позже
- Кэшировать summary (обновлять раз в N ходов).
- Добавить «режим мастера» (ручная корректировка).
- Добавить сохранения/загрузки.
